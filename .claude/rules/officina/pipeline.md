# Officina パイプライン — 11 ステージ ＋ 2 人間ゲート

このファイルは Officina のパイプライン全体図です。コード上の正本は
`src/officina/pipeline.py`(`PIPELINE` タプル)です。両者は同期させること。

各ステージ = 担当エージェント / 主な出力 / 合格ゲート(テストスイート相当)/
決定論ゲート / 人間の関与。

## 進行ルール

第一に、**合格ゲートが緑でないステージの出力を次へ流さない**。テストスイート相当の合格基準を満たして初めて進行する。

第二に、**決定論ゲートは実行前に通す**。送信・課金・本番デプロイ・契約確定は、対応するゲート(`gates.py`)が `allowed=True` を返すまで実行しない。

第三に、**人間ゲートでは待つ**。ステージ 7(契約締結)とステージ 9(納品物承認)は人間の応答が来るまで進行停止。AI が署名・出荷を代行しない。

第四に、**例外のみ人間に上げる**。Qualifier(ステージ3)・Proposer(ステージ5)の例外エスカレーションは恒常作業ではなく例外処理。

## ACV による自律度の分岐

```yaml
acv_bands:
  low:    # < $25k 相当・単純意思決定
    closing: ai_led_assist     # ステージ6を AI 主導で進めやすい
  mid:
    closing: hybrid            # 人間厚め
  high:   # >= $50k・複数ステークホルダー
    closing: human_led         # ステージ6は人間主導(必須)
# 契約署名(ゲートA)と納品承認(ゲートB)は ACV に関係なく常に人間。
```

## Phase 計画(自律比率を "稼いで" 上げる)

- **Phase 1(今すぐ)**: ハイブリッド前提。ステージ 0-5 ＋ 8-11 を自律、6-7・9 を人間。低 ACV・単純意思決定から。1 案件で全工程を通す。
- **Phase 2**: 各ゲートの合格データが溜まったら、Qualifier/Proposer の例外エスカレーション率を下げ、人間の関与を例外のみに。
- **Phase 3**: クロージングの一部(低額・単純)を AI 主導に拡張。契約署名は人間維持。
- **asymptote(漸近線)**: 人間ゲートは契約署名と納品承認の 2 点に固定。ここは恒久的に人間。自律の "上限" を正しく認める。

## KPI(虚栄指標を排す)

- deliverability 健全性(バウンス率・スパム苦情率・ドメイン評価)← **最優先・日次監視**
- 返信率 → **商談実施率(booked→held)** → 商談化 → **クローズドウォン**
- 各ゲート合格率(ステージ別の自動合格基準の通過率)
- リジェクトログ件数と再発率
- 案件あたり粗利・本番保守コスト(0.25〜0.5 人月/体を織り込む)

### 撤退/見直しトリガー
- スパム苦情率の上昇 → 即アウトリーチ監査
- クローズドウォン率がハイブリッド基準を継続下回る → クロージング設計見直し
- ゲート合格率が閾値割れ → 該当工程の自律を一時停止し人間比率を上げる
