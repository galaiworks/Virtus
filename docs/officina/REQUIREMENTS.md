# 自律型AIエージェンシーOS 要件定義書 v0.1

**プロジェクト名（仮）:** Officina（オフィキナ／"工房・作業場"の意）
**目的:** 営業から納品までを自律エージェントチームで回し、人間（ガライ）の接触点を「2つのゲート」に圧縮する。
**ステータス:** ドラフト。判断が分かれる箇所は §12 に列挙。ここに反応をもらって v0.2 に進む。
**前提モデル:** 「完全無人」ではなく「人間1人が2ゲートを所有する逆ピラミッド」。根拠は §3。

> 注: 本ファイルは v0.1 の原文を保存したもの。§12 への暫定回答と実装は
> [OFFICINA.md](../../OFFICINA.md) の「v0.2 作業前提」を参照。

## 1. ゴール定義と非ゴール

### 1.1 ゴール
営業リサーチ → アウトリーチ → 商談・要件抽出 → 提案 → クロージング補助 → **【人間】契約締結** → 開発（要件定義〜実装〜検証）→ **【人間】納品物承認** → 納品 → アフター（請求・保守・アップセル）を、エージェントチームが自律実行する。人間の総作業を「ICP承認＋2ゲート」に最小化する。

### 1.2 非ゴール（意図的に外す）
- **クロージングの完全自律化**：高額・複数意思決定者の案件で人間判断を外すことは、世界のデータ上の代表的失敗（§3）。AIは"補助"まで。
- **契約署名の自律化**：法的に取り消せない行為。署名主体は常に人間。
- **納品物の無人出荷**：賠償リスクが乗る不可逆行為。最終承認は人間。
- **士業の独占業務に踏み込む納品**：税理士・弁護士業務等は別棚（§8.4）。

## 2. 設計原則（このプロジェクトの憲法）

1. **自律可能性 = 検証可能性 × 可逆性。**
2. **テストスイート＝決定論的ゲートの一般化。** 各工程に「テストスイート相当の合格基準」を必ず定義する。
3. **オーケストレーター・ワーカー型。** "God Model" は禁止。
4. **検証は独立エージェントで。** 生成と検証を同一エージェントに兼務させない。
5. **決定論ゲートはLLMに判断させない。** 送信量上限・契約トリガー・課金・本番デプロイは if/then のハードロジックで強制。
6. **リジェクトログ＝リグレッションテスト。**

## 3. グローバル勝ち筋の要約（モデリング根拠 / 2026年6月時点）

- **ハイブリッドが売上で勝つ。** AI単独 847商談@11% vs ハイブリッド 312商談@38%。少商談でも売上約2.3倍。
- **純AIは成約で負ける。** クローズドウォンで純AI構成はハイブリッドに約22ポイント劣後。フル自律の長期定着は約2%。
- **撤退の主因はクロージング不全ではなく到達不全。** 過剰自動送信でドメイン評価が崩壊し、試行の約47%が90日で頭打ち。
- **成否の80〜90%はデータ配管・ルーティング・ガードレール、プロンプトは10〜20%。**
- **ACV閾値。** 概ね $25k未満の単純な意思決定ならAI主導が機能。$50k超・複数ステークホルダーは人間必須。
- **エージェンシー経済圏。** 2人で月商$42k、または年商$320k→$890kを増員なしで達成した事例。
- **本番運用コスト。** 本番エージェント1体あたり 0.25〜0.5人月/継続の保守。

**結論:** AI単独の自律ではなく、上記の勝ち筋を最大化する設計に振る。

## 6. ガバナンス3層

### 6.1 決定論ゲート層（LLMに判断させない）
送信量・頻度上限、ウォームアップ制御、opt-out即時反映 / 価格ガードレール / 契約トリガー・課金・本番デプロイ / ゼロトラスト権限。

### 6.2 Guardian独立検証層
生成物を統合前に合格基準へ照合 / 発見→別エージェントが反証→収束 / 評価プローブ＋ドリフト監視。

### 6.3 人間HITLゲート層（2点のみ）
ゲートA：契約締結 / ゲートB：納品物 最終承認 / ＋例外エスカレーション。

## 7. 人間（ガライ）の役割定義

1. ICP・戦略の承認（ステージ0）
2. 高額案件のクロージング判断（ステージ6）
3. 契約署名（ゲートA・必須・不可逆）
4. 納品物の最終承認（ゲートB・必須・不可逆）

---

## 8. 法務・コンプライアンス（要・専門家確認）

- **8.1 自律アウトリーチ**: 特定電子メール法 / GDPR / CAN-SPAM。deliverability防衛が事業継続条件。
- **8.2 プラットフォーム規約**: SNS自動アウトリーチは規約エンフォースメント対象。チャネル分散。
- **8.3 契約・署名**: 署名は必ずガライ。
- **8.4 納品物の業法**: 士業の独占業務は自律納品から外し、有資格者の倍率装置として別設計。
- **8.5 ブランド・幻覚リスク**: 高額・経営層には人間の質感を残す。Prospector出力はGuardianで実在性検証。

## 10. KPIと撤退基準

### 10.1 ファネルKPI
deliverability健全性（日次） / 返信率→商談実施率→商談化→クローズドウォン / 各ゲート合格率 / リジェクトログ / 粗利・保守コスト。

### 10.2 撤退/見直しトリガー
スパム苦情率上昇→即監査 / クローズドウォン率がハイブリッド基準を下回る→クロージング設計見直し / ゲート合格率割れ→該当工程の自律一時停止。

---

## 11. フェーズ計画

- **Phase 1**: ハイブリッド前提。0-5＋8-11を自律、6-7・9を人間。低ACVから。
- **Phase 2**: 例外エスカレーション率を下げ、人間関与を例外のみに。
- **Phase 3**: 低額・単純クロージングをAI主導に拡張。署名は人間維持。
- **asymptote**: 人間ゲートは契約署名と納品承認の2点に固定。

---

## 12. オープンな決定事項（ガライに確認したい判断点）

1. **初期ターゲットACV帯**: 低ACV高ボリュームか、中ACVから人間厚めか。
2. **納品物の標準型**: クライアント向けエージェント構築に絞るか、広く取るか。
3. **シグナル層の自前/連携**: 自前構築か外部データ連携か。
4. **法人化との接続**: 法人スキームをこのOSの前提に組み込むか。
5. **deliverabilityインフラ**: 内製か専用ツールか。
